## 1. คุณสมบัติของ World-class Developer

World-class developer ไม่ใช่แค่คนที่เขียน code เก่ง แต่คือคนที่สร้าง impact ที่ใหญ่กว่าตัวเอง

### Technical Excellence

**Code Quality:**
- เขียน code ที่คนอื่นอ่านและ maintain ได้ง่าย
- Test coverage สูงและ tests ที่ meaningful
- Performance-conscious ในทุก decision
- Security-first mindset
- เข้าใจ trade-offs ของทุกการตัดสินใจ

**System Thinking:**
- มองเห็นภาพรวมของ system ทั้งหมด
- เข้าใจ bottlenecks และ points of failure
- ออกแบบสำหรับ failure (fault tolerant)
- คิดถึง scalability ตั้งแต่วันแรก แต่ไม่ over-engineer

**Continuous Learning:**
- ติดตาม ecosystem อย่างใกล้ชิด
- อ่าน source code ของ libraries ที่ใช้
- Experiment กับ new technologies
- เรียนรู้จาก production incidents

## 4. Leadership Skills

World-class engineer ต้องมีทักษะ leadership แม้จะไม่ได้เป็น manager:

### Technical Leadership

**Decision Making:**
- วิเคราะห์ trade-offs อย่างชัดเจน
- กล้า commit กับการตัดสินใจที่ยาก
- ยอมรับเมื่อผิดและ course-correct เร็ว

**Communication:**
- อธิบาย technical concepts ให้ non-technical stakeholders ได้
- เขียน well-structured proposals
- Active listening ในการประชุม

**Influence:**
- สร้าง trust ด้วย track record ที่ดี
- ไม่รอให้มีอำนาจ - influence ด้วยความรู้และ respect

### People Skills

- **Empathy:** เข้าใจว่า junior devs กำลังเรียนรู้อยู่
- **Patience:** การ mentor ต้องใช้เวลา
- **Feedback:** ให้ feedback ที่ specific และ actionable
- **Recognition:** ชื่นชม contribution ของทีม

## 5. Innovation Mindset

### คิดแบบ Engineer ที่ดีที่สุด

**First Principles Thinking:**
ถามว่า "ทำไม" ก่อนเสมอ ไม่ใช่แค่ทำตาม best practices โดยไม่เข้าใจ

```
ทำไมต้อง SSR?
→ เพราะ SEO และ faster first paint
→ แต่ app เราเป็น dashboard ที่ user ต้อง login
→ SEO ไม่สำคัญ ดังนั้น CSR อาจดีกว่า
```

**Systems Thinking:**
มองทุกอย่างเป็น system ที่ interconnected ไม่ใช่ isolated components

**Experimentation:**
- ทำ PoC ก่อน commit ใหญ่
- Measure ทุกอย่าง
- ยอมรับว่า experiment อาจ fail

## 8. Mentoring Others

การสอนคนอื่นเป็นวิธีเรียนที่ดีที่สุด และช่วยให้ ecosystem เติบโต

### How to Mentor Effectively

**สร้าง Safe Environment:**
ให้ mentee รู้สึกสบายใจที่จะถามคำถาม "โง่" ไม่มีคำถามที่โง่

**Guide, Don't Give Answers:**
```
❌ "แก้โค้ดนี้ให้ mentee ตรงๆ"

✅ "ลองดูว่า error message บอกว่าอะไร?"
   "อะไรน่าจะเป็นสาเหตุที่ทำให้เป็นแบบนี้?"
   "มีวิธีไหนบ้างที่จะ debug ได้?"
```

**Regular 1:1:**
- ถามถึง goals และ challenges
- Track progress อย่าง explicit
- ให้ feedback ที่ honest แต่ kind
